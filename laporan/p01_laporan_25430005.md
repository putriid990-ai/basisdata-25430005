\## 6. Penerapan Idempotensi SQL



Pada praktikum digunakan perintah `IF NOT EXISTS` untuk membuat SQL lebih aman ketika dijalankan berulang kali.



Contohnya:



CREATE DATABASE IF NOT EXISTS kopma\_123;



CREATE TABLE IF NOT EXISTS produk (

&#x20;   id INT PRIMARY KEY,

&#x20;   nama VARCHAR(100)

);



Dengan penggunaan `IF NOT EXISTS`, perintah tidak menyebabkan kesalahan ketika database atau tabel yang dimaksud sudah tersedia.



Penerapan ini membuat script SQL lebih aman untuk dijalankan kembali dan mengurangi risiko kegagalan akibat objek database yang sudah dibuat sebelumnya.



\## 7. Analisis Praktikum



\### Analisis 1 — Hak Akses Pengguna



Hak akses pengguna diperlukan untuk membatasi aktivitas yang dapat dilakukan pada database. Setiap pengguna diberikan hak sesuai dengan kebutuhan tugasnya sehingga keamanan dan pengelolaan data dapat lebih terkontrol.



Dalam praktikum ini, `mhs\_123` memiliki hak akses penuh pada database `kopma\_123`, sedangkan `tamu\_123` hanya diberikan hak SELECT. Perbedaan tersebut menunjukkan bahwa hak akses dapat diberikan secara spesifik kepada setiap pengguna.



\### Analisis 2 — Perbedaan Hak Akses



Perbedaan hak akses dapat dilihat dari kemampuan pengguna dalam menjalankan perintah SQL.



`mhs\_123` dapat melakukan operasi pada database `kopma\_123` sesuai hak akses penuh yang diberikan.



Sementara itu, `tamu\_123` hanya dapat melakukan operasi SELECT sehingga tidak dapat membuat tabel baru. Ketika mencoba menjalankan perintah CREATE TABLE, sistem menghasilkan ERROR 1142.



Pembagian hak akses seperti ini membantu mencegah pengguna melakukan perubahan yang tidak sesuai dengan kewenangannya.



\### Analisis 3 — Idempotensi SQL



Idempotensi SQL berarti sebuah script dapat dijalankan kembali tanpa menyebabkan kesalahan karena objek database atau tabel sudah tersedia.



Dalam praktikum digunakan:



CREATE DATABASE IF NOT EXISTS kopma\_123;



dan:



CREATE TABLE IF NOT EXISTS produk (

&#x20;   id INT PRIMARY KEY,

&#x20;   nama VARCHAR(100)

);



Kata `IF NOT EXISTS` membuat perintah memeriksa terlebih dahulu apakah objek sudah tersedia. Jika sudah ada, sistem tidak membuat objek yang sama kembali.



Penerapan idempotensi membuat script lebih aman, mudah digunakan kembali, dan mengurangi kesalahan saat proses instalasi atau pengujian database.



\### Analisis 4 — Perbedaan ERROR 1044, 1045, dan 1142



Ketiga error tersebut menunjukkan masalah yang berbeda.



\*\*ERROR 1044\*\* terjadi ketika pengguna berhasil dikenali oleh sistem, tetapi tidak memiliki izin untuk mengakses database tertentu. Dalam praktikum, `dev\_123` mendapatkan ERROR 1044 ketika mencoba mengakses `kopma\_123`.



\*\*ERROR 1045\*\* terjadi ketika proses autentikasi atau login gagal. Contohnya ketika username atau password yang digunakan tidak sesuai.



\*\*ERROR 1142\*\* terjadi ketika pengguna sudah berhasil login dan dapat mengakses database, tetapi tidak memiliki izin untuk menjalankan perintah tertentu. Dalam praktikum, `tamu\_123` mendapatkan ERROR 1142 ketika mencoba membuat tabel karena hanya memiliki hak SELECT.



Dengan demikian, perbedaannya dapat diringkas sebagai berikut:



| Error | Penyebab |

|---|---|

| 1044 | Tidak memiliki akses ke database tertentu |

| 1045 | Gagal melakukan autentikasi/login |

| 1142 | Tidak memiliki izin menjalankan perintah tertentu |
